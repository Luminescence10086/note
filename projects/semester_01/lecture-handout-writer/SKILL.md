# 讲义编写与 PDF 生成 Skill

## 触发条件

当用户表达以下意图或编写者有以下意图时触发本技能：

- "写一份《XXX》讲义"
- "出一份 XXX 课程的教学材料"
- "帮我做一门课的 handout"
- "编写 XXX 教材/讲义"

## 总体流程

本 Skill 采用分阶段流水线，阶段之间靠书面契约交接，互不读取对方的中间产物：

1. 阶段 0：初始化 — 创建工作目录与进度文件，确认输出格式（md / pdf）
2. 阶段 1：教学定位（含 Gate 1）— 确认受众、深度、篇幅，产出 UbD 五件套：核对课程进度
3. 阶段 2：章节规划（含 Gate 2）— 产出章节树与 Bloom 梯度报告：核对学习次序
4. 阶段 3：逐章写作 — 按四段式结构逐章撰写正文
5. 阶段 4：题目生成与核验 — 生成三类题并核验答案
6. 阶段 5：审稿与归档 — 送学科审稿员审稿 → 按意见修订 → 定稿入 approved/；如需 PDF 则编译

## 阶段 0：初始化

### 0.1 确认输出格式（作者选择）

先核对输出格式；用户已指定则直接记录，否则向作者确认：

- Markdown（.md）：默认，与学习系统现有讲义体系一致，审稿员直接读取 .md 审稿
- PDF（LaTeX）：作者需要 PDF 版；写作阶段仍以 Markdown 编写，定稿后编译为 PDF
- 两者都要：Markdown 定稿 + 附加 PDF 编译

作者选择记录在 .progress.json 的 format 字段，全流程按此执行。

### 0.2 创建目录结构

```
讲义项目/
├── .progress.json          # 进度文件（断点续写用）
├── 00-讲义设计.md           # 教学定位 + UbD 五件套
├── 01-<第一章标题>.md      # 各章 LaTeX 源文件
├── 02-<第二章标题>.md
├── ...
└── 术语表.md              # 术语表
        
```

> 存放约定（用户 2026-08-20 明确）： 讲义成品最终只保留在 lectures/<学科>/approved/ 目录（定稿区）； lectures/<学科>/ 根目录不暴露讲义文件（只留 README.md 与子目录）。 送审/修订过程文件放临时路径或工作过程目录，定稿后移入 approved/。 写入 \wsl$ 工作区如遇原子重命名问题（ENOTSUP），按 .harness/workaround.md 的绕行方案执行。

### 0.2 进度文件格式

```json
{
  "project": "讲义名称",
  "discipline": "stem | humanities",
  "format": "md | pdf | both",
  "phase": 1,
  "gate1_confirmed": false,
  "gate2_confirmed": false,
  "chapters_written": [],
  "chapters_pending": []
}
```

## 阶段 1：教学定位（Gate 1）

### 1.1 一轮提问

向用户确认以下信息：

- 目标受众：写给谁？（本科生/研究生/从业者）
- 知识深度：多深？（入门/中级/高级）
- 篇幅规模：多大？（预计多少页/多少章）
- 学科类型：stem（理工科，答案可复算）还是 humanities（人文社科，答案依赖论证）

### 1.2 核对课程进度

- 读取 learning_path.md 与 learning_progress.md，确认本讲义对应的课程进度位置（学期/模块/任务编号）。
- 学习次序红线：不得把尚未学过的概念/定理默认为读者已知；需要后续课程才定义的对象，须标注"后续课程引入"或补前置铺垫。 

### 1.2 产出 UbD 五件套

基于用户回答，产出：

1. 学习目标：学生学完能做什么
2. 评估证据：如何证明学生达到了目标
3. 学习活动：学生需要做什么来达成目标
4. 内容结构：知识的主线与分支
5. 术语表草案：关键术语的初步定义

### 1.3 ⏸ Gate 1：等待用户确认

产出 UbD 五件套后必须停下来，等待用户明确确认或提出修改意见。
Gate 1 确认语（以下为示例，其他语义明确的确认亦有效）：

- "确认，继续"
- "确认，但修改 XXX 为 YYY"
  在 Gate 1 确认之前，不得进入阶段 2。

## 阶段 2：章节规划（Gate 2）

### 2.1 产出章节树

基于已确认的 UbD 五件套，倒推：

- 全书章节划分与逻辑顺序
- 每章的核心知识点
- 章节之间的依赖关系
- 每章建议的 Bloom 层级分布

### 2.2 核对学习次序

- 逐章核对引用的每个概念、记号、定理是否在既定课程进度内已教过；
- 发现"超前引用"（用到后续课程才定义的对象）须在规划中明确指出，建议补前置铺垫或推迟引入。 

### 2.3 产出 Bloom 梯度报告

检查全书各章节的认知层级分布是否合理（从记忆/理解到分析/评价/创造应有梯度）。

### 2.4 ⏸ Gate 2：等待作者确认

产出章节树与 Bloom 报告后必须停下来，等待用户明确确认或提出修改意见。
Gate 2 确认语（以下为示例，其他语义明确的确认亦有效）：

- "确认，继续"
- "确认，但调整 XXX 章节顺序"
  在 Gate 2 确认之前，不得进入阶段 3。

## 阶段 3：逐章写作

### 3.1 每章四段式结构

每章按以下四段式结构撰写：

1. 章引言：本章要解决什么问题、与前后章的关系
2. 概念讲解：核心概念的定义与解释
3. 示范例题/案例分析：理科为示范例题（带完整解答），文科为案例分析
4. 本章小结：回顾核心要点，预告下一章

### 3.2 公式格式标准（审稿硬性要求）

数学公式一律遵守：

- Markdown 公式使用单美元配对 `$...$`，独立成行亦如此，不使用双美元；
- 行内公式 `$...$` 与中文之间保持空格；
- 公式内不得有多余或缺失的 $。

### 3.3 术语表一致性维护

写作过程中持续维护术语表：

- 每个关键术语首次出现时加粗
- 同一术语在全书中保持同一译名
- 术语定义以术语表为准

### 3.4 输出格式

- 写作阶段一律产出 Markdown（.md）源文件，与学习系统现有讲义体系一致（审稿员直接读取 .md 审稿）；
- 若阶段 0 选择 pdf 或 both：定稿并审稿通过后，按 references/pdf-production.md 编译为 PDF（源 .md 保留）。

## 阶段 4：题目生成与核验（不可妥协的底线）

### 4.1 生成三类题

每章生成三类题：

1. 示范例题：带完整解答，展示解题/论证思路
2. 引导练习：带提示，学生可尝试
3. 独立习题：不带提示，供学生独立完成

### 4.2 答案核验（红线）

每道题的答案必须核过才输出：

- 理科（stem）：必须真算复核。将题目与答案代入原问题验证，确认数值、符号、单位全部正确。
- 人文社科（humanities）：必须核对来源与引文出处。逐字核对引文原文、确认页码与版本。
  验证不了的，一律标注 ⚠️ 需作者确认，绝不假装已验证。
  学科可以换，纪律不换。档案能定义"用什么方式验证"，不能定义"是否需要验证"。

### 4.3 题目在 LaTeX 中的格式

- 示范例题：用 \begin{example} ... \end{example} 环境
- 引导练习：用 \begin{exercise}[hint] ... \end{exercise} 环境
- 独立习题：用 \begin{problem} ... \end{problem} 环境

## 阶段 5：审稿与归档

### 5.1 送学科审稿员审稿

讲义初稿完成后：

1. 在 signals/review_request/<学科>/ 创建送审信号文件（如 signals/review_request/math/YYYYMMDD_讲义名.signal），经哨兵唤醒学科审稿员（Reviewer_MATH 等）。
2. 审稿员审阅讲义并给出意见（通过/需修改 + 逐条建议）。

### 5.2 修订

采纳审稿意见修订讲义；修订后重新送审直至通过。

### 5.3 定稿归档

审稿通过后（signals/review_approved/<学科>/ 有批准信号）：

- 讲义移入 lectures/<学科>/approved/；
- 文件名按现有命名规则（NN_<主题>.md）；
- 归档前教务长复核跨学科交叉；若涉及交叉，先在 signals/review_request/cross/ 创建信号，向可用且已获授权的 Cross_Reviewer 提交路径及学科，等待真实综合意见。一致后才归档；有矛盾则协调教授与审稿员，修订复审。

### 5.4 审稿格式注意事项（与审稿标准一致）

- Markdown 公式使用单美元配对 `$...$`，不得用双美元；
- 不得超前引用未学概念；
- 引文/数据/论断强度必须保护：不改变原始数据、引文和核心论断。

## 阶段 6：可选 LaTeX/PDF

仅在选择 pdf、both 或明确要求编译时，读取 [references/pdf-production.md](references/pdf-production.md)。保留 Markdown 源。

## 关键原则（贯穿全流程）

原则 1：关键决策由作者拍板
Gate 1 和 Gate 2 是两个检查点，AI 给出草案后停下来等作者确认——职责是逼你想清楚，不是替你做主。

原则 2：诚实优先于流畅
验证不了的结论宁可标注「需作者确认」，也不输出一个看起来自信的编造结果。

原则 3：保护证据与论断强度
引用、数据、研究局限和论断强度在 AI 处理过程中必须被保护。不改变用户提供的原始数据、引文和核心论断。

原则 4：流水线代替一口气写完
各阶段之间靠书面契约交接，互不读取对方的中间过程——这是长讲义写得完、每章质量稳定的工程保证。

原则 5：由浅入深，从直觉或具体例子引入，再过渡到抽象概念和形式化定义。

原则 6：为复杂概念提供生动、贴切的日常类比，降低理解门槛。

原则 7：尊重学习次序与审稿纪律 讲义必须符合课程进度（不超前引用未学概念），并完整走审稿 → 修订 → 归档流程，未经审稿不得定稿。

## 断点续写

若中途中断，用户重新输入同一句话（如"继续写《XXX》讲义"），系统从 .progress.json 读取进度，从断点处继续。

## 使用示例

| 用户说           | 触发阶段             |
| ------------- | ---------------- |
| "写一份《线性代数》讲义" | 从阶段 0 开始，走完全流程   |
| "确认，继续"       | 通过当前 Gate，进入下一阶段 |
| "按大纲写第三章"     | 阶段 3（逐章写作）       |
| "出几道矩阵乘法的练习题" | 阶段 4（题目生成与核验）    |
| "编译为 PDF"     | 阶段 6（LaTeX 编译）   |

## 存储路径

- 定稿：lectures/<学科>/approved/（仅成品，根目录不暴露讲义文件）
- 过程文件：临时路径或工作过程目录，定稿后移入 approved/
- 写入 \wsl$ 工作区如遇原子重命名问题（ENOTSUP），按 .harness/workaround.md 的绕行方案执行。

## 命名规则

- 定稿文件按 NN_<主题>.md 命名（如 01_向量空间与子空间.md），与现有讲义体系一致；
- PDF 附加产物（如有）同名 .pdf，放 approved/ 同目录。

## 元数据

在文件顶部使用 YAML Frontmatter 记录基本信息：
    ```yaml
    ---
    title: 讲义标题
    subject: 学科名称
    author: [教授角色名]
    date: 编写日期
    version: 1.0
    ---
    ` 

## 执行范围与状态真实性

- 从请求所需的阶段开始；单章写作、出题或编译复用已有明确确认的设计，不强制重启整书流程。
- Gate 1 与 Gate 2 尚未获确认时，展示可审阅草案后等待，并说明本 Skill 的对应要求及本文件链接。已有授权不重复索要。
- 各阶段依靠已确认书面契约交接，可读取必要设计、术语与验证结果；不依赖未确认中间草稿。
- 进度文件缺失时记录假设，不编造课程进度。每阶段交接和每章完成后更新 .progress.json；续写核对实际文件。
- 送审信号不等于审稿员已运行。批准必须对应当前版本；缺少审稿通道时保留待审，不模拟通过。
- 未验证答案明确标记，不能作为已验证成品归档；无页码引文记录章节或段落，不虚构页码。
- 归档时更新已有 learning_progress.md 中相关讲义状态；讲义完成不等于学生学习完成。
- 上述路径为 AI 学习系统约定；其他项目遵循用户指定路径和审稿机制，不清理无关文件。
- WSL ENOTSUP 绕行仅在项目实际存在 .harness/workaround.md 时读取应用，缺失则报告实际错误。
